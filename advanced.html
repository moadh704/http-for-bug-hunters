Module 06

Where messages break

Smuggling, cache poisoning, and downgrade bugs are the same story: two readers, one byte stream, two opinions.

Length versus chunks

HTTP/1.1 can size a body with Content-Length or with chunked Transfer-Encoding. A request that carries both asks two questions. If the front parser answers one and the back parser answers the other, the leftover bytes become the start of the next user's request.

You do not need a working desync to understand the report. You need to say which hop used which length, and what the leftover bytes were. Build that on a lab that documents smuggling. Do not run it against a customer you have not been told to test.

Cache keys are a second request

A cache stores a response under a key, usually the method, host, and path, plus whatever Vary adds. If the body depends on a header that is not in the key, the first response is served to everyone. Unkeyed headers and unkeyed query parameters are the things you inventory.

Poisoning means you can choose the body that gets stored. Deception means you can choose a path the cache thinks is static and the app thinks is private. Both are header and key problems, not payload problems.

The upgrade and the socket

A WebSocket starts as an HTTP request with Upgrade: websocket and a 101 response. After that the bytes are no longer HTTP. If an access check only exists on the HTTP route and not on the upgraded socket, the check ended at the handshake.

HTTP/2 and HTTP/3 change framing again. When a lab asks you to downgrade, it is asking you to watch the translation, the same skill as module 01.

JWT in an Authorization header is still just a header. Decoding the middle segment is base64, not an attack. Trust starts where the server checks the signature.

Check yourself

Three questions. Nothing unlocks. A pass is just a mark in this browser so you know you read it.

  1. Request smuggling requires

    One hop ends the message in a different place than the next. The leftover bytes are prefixed onto another request.

  2. A cache poisoning bug is mainly about

    If you control an unkeyed input and the cache stores the result, later visitors receive your response.

  3. After a WebSocket 101,

    The handshake is the last HTTP message. Authorization that is not repeated inside the protocol is not repeated at all.
