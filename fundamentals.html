Module 01

The message

HTTP is a conversation of messages, not pages. If you can read one request and one response on the wire, every later bug class gets quieter.

One transaction

A client opens a connection and sends a request. The server sends one response. HTTP/1.1 then usually keeps the socket open for the next message. That reuse is why the end of one message has to be unambiguous.

If two parsers disagree about where a message ends, the next bytes belong to a different request than you think. That single fact is the root of request smuggling. You do not need a payload yet. You need to see the boundary.

POST /login HTTP/1.1
Host: app.example
Content-Type: application/x-www-form-urlencoded
Content-Length: 27

user=ada&password=hunter2

The blank line is the boundary. Everything after it is body, and Content-Length says how many bytes that body is.

Three parts, different jobs

The start line names the method, the target, and the version. Headers are the control plane: who the request is for, how long the body is, which cookies ride along, whether a cache may store the result. The body is optional and only means something because a header said how to read it.

Hunters read headers before they read the body. A 200 with a surprising Content-Type, a missing Content-Length, or a Host you did not type is more interesting than the HTML inside.

Text on the wire, frames after the proxy

What you type in a repeater is usually HTTP/1.1 text. Between the browser and the edge, and between the edge and the app, the same request may be HTTP/2 frames. The method, path, and headers survive. The framing does not.

That translation is where desync bugs live. One hop trusts Content-Length. The next trusts chunked framing. Your job in a lab is to notice two parsers, not to memorize a cheat sheet of bytes.

Practice this on a local proxy and a lab you are allowed to test. Do not point a smuggling proof at a site you do not own.

Check yourself

Three questions. Nothing unlocks. A pass is just a mark in this browser so you know you read it.

  1. Where does an HTTP/1.1 header block end?

    Headers end at the blank line (CRLF CRLF). The body, if any, starts after that.

  2. Why does Content-Length matter to a hunter?

    The length is the message boundary. A second parser that ignores it will attach the leftover bytes to the next request.

  3. What usually changes when a proxy turns HTTP/2 into HTTP/1.1?

    Method, path, and headers are preserved. The way the message is framed is rewritten, and that rewrite is where disagreement starts.
