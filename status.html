Module 04

Status codes

The status line is the server's one-sentence opinion. Compare it to the body. They often disagree, and the disagreement is the bug.

2xx is not a clean bill

200 means the server produced a response it is willing to call successful. It does not mean you were authorized, and it does not mean the action was a no-op. GraphQL and some JSON APIs return 200 with an errors array. Always read the body when the status looks too calm.

204 and 304 are interesting because they have no body. A 304 that still updates a cache, or a 204 from a route that should have created something, is a logic smell.

Redirects are requests you did not type

301 and 302 tell the client to go somewhere else. If Location is built from your input, you have an open redirect, and sometimes a header injection if a newline survived. 307 and 308 keep the method and body. A 302 that turns a POST into a GET can drop a token that a 307 would have forwarded.

Watch the hop count. A login that redirects three times may set the session on a hop you are not looking at.

401, 403, 404, 405

401 means you need to authenticate. 403 means the server knows you and still refuses. When an object you should not see returns 403, and a missing object returns 404, the difference confirms the object exists. That is an identifier oracle.

500 after a single quote, a long string, or a changed content type is a parsing bug, not proof of injection. Note the input that flipped the status, then reproduce it once in a lab before you call it anything.

Write down the pair: same request, one field changed, status changed. That pair is your evidence.

Codes you will actually see

    Check yourself

    Three questions. Nothing unlocks. A pass is just a mark in this browser so you know you read it.

    1. A JSON API returns HTTP 200 and a body field errors. You should

      Many APIs tunnel their own errors inside a 200. The status line is only the first opinion.

    2. 403 for a real id and 404 for a fake id means

      The split is an oracle. You learned the id is real without being allowed to read it.

    3. 307 differs from 302 because

      302 historically gets replayed as GET. 307 and 308 must not change the method.
